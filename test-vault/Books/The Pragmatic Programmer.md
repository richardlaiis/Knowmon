# The Pragmatic Programmer

A collection of practical advice for working programmers. The ideas I want to keep:

- **Tracer bullets**: build a thin version of the whole system end to end first, then fill it in. Unlike a prototype, the tracer code is kept.
- **DRY** is about knowledge, not text: two identical-looking functions that encode different rules aren't duplication.
- **Orthogonality**: components that don't affect each other are easier to change and test.
- **Don't live with broken windows**: fix small messes before they signal that nobody cares.
- **Good-enough software**: involve users in deciding when it's good enough.

Applied to Knowmon: the Q&A feature started as a tracer bullet ([[2026-10-21]]), and the [[Dev log]] shows each part being thickened afterwards.
