# 屬性（Frontmatter）

屬性是寫在筆記最開頭、用兩條 `---` 包起來的 YAML 區塊，用來記錄關於這篇筆記的資訊（又稱 frontmatter）：

```markdown
---
date: 2025-12-20
author: James Clear
tags: [書, 習慣]
---

# 原子習慣

1. 讓提示顯而易見
   …
```

屬性區塊在編輯器中以等寬字、較淡的顏色與底色顯示，裡面的文字不會套用 Markdown 渲染。屬性區塊是可選的，不寫也完全沒問題。

## Knowmon 會使用的屬性

| 屬性   | 用途                                             | 範例               |
| ------ | ------------------------------------------------ | ------------------ |
| `date` | 這篇筆記的**事件日期**：內容講的事情發生在哪一天 | `date: 2026-10-01` |
| `tags` | 標籤。Agent 的「加標籤」功能會寫入這裡           | `tags: [書, 習慣]` |

其他屬性（例如 `author`、`title`、`status`）Knowmon 都會原樣保留，只是不會特別處理。

> **注意**：屬性區塊**不會**被搜尋與 AI 檢索索引。想讓某個詞被搜尋到，請寫在內文裡。

### `date`：事件日期

`date` 告訴 Knowmon「這篇筆記講的是哪一天的事」，它會影響：

- **時間軸**的「Event date」模式：筆記被排在這一天。
- **圖譜的時間邊**：Same day（同一天的筆記相連）與 Sequence（同資料夾的前後篇相連）。
- **時間篩選**：圖譜的時間滑桿、Hybrid 搜尋的日期範圍、AI 問答中「上個月」「2026-10-04」這類條件。

支援的寫法：

```yaml
date: 2026-10-01
date: 2026/10/1
date: 2026.10.01
date: 2026-10-01 14:30 # 只取日期部分
```

**沒有 `date` 時**，Knowmon 會看檔名是否以 `YYYY-MM-DD` 開頭，例如 `2026-10-06.md`、`2026-10-06 週會.md`。兩者都沒有的筆記就是「沒有事件日期」，這很正常：讀書心得、概念整理這類筆記本來就不屬於某一天。

> **範例**：10 月 8 日補寫 10 月 1 日的會議紀錄。只要寫上 `date: 2026-10-01`，它在時間軸上就會出現在 10/1，而不是你動筆的 10/8。至於「什麼時候寫的」，Knowmon 會另外自動記錄，見 [時間脈絡](time.md)。

### `tags`：標籤

以下三種寫法都可以：

```yaml
tags: [書, 習慣]
```

```yaml
tags:
  - 書
  - 習慣
```

```yaml
tags: 書
```

目前 Knowmon 沒有專門的標籤面板，標籤的主要用途是：

- 讓 [Agent](agent.md) 幫你分類（「幫上週的日記加上『回顧』標籤」）。
- 與其他工具相容（Obsidian 等也讀 `tags`）。

Agent 加標籤時只會修改 `tags` 那幾行，盡量保留你原本的寫法；比對既有標籤時不分大小寫、忽略 `#`，已經有的標籤不會重複加。

### `title`

筆記的標題**一律是檔名**。frontmatter 裡的 `title:` 只是一般屬性，不會改變筆記在檔案樹、連結或圖譜中顯示的名稱。要改標題請直接改名。

## 小提醒

- 屬性區塊必須在檔案的**第一行**就開始。
- YAML 寫錯（例如引號沒有關）時，Knowmon 會把整份文件當作沒有屬性，不會報錯，也不會改動你的檔案。這時 `date` 不會生效，Agent 也會拒絕修改這篇的標籤。
