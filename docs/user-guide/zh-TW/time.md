# 時間脈絡

大部分筆記軟體只靠你手寫的連結來串起筆記。但很多關聯其實藏在「時間」裡：同一個下午一起寫的幾篇筆記，往往在思考同一件事；同一天的日記、會議紀錄、讀書心得，常常彼此有關。

Knowmon 會自動記下你何時寫了哪些筆記，並用時間把筆記連起來。你什麼都不用做，只要照常寫筆記。

## 兩種時間

每篇筆記有兩種時間，用途不同：

|            | 事件時間（Event date）                                | 寫作時間（Written）          |
| ---------- | ----------------------------------------------------- | ---------------------------- |
| 意思       | 筆記內容講的事**何時發生**                            | 你**何時建立、編輯**這篇筆記 |
| 來源       | frontmatter 的 `date:`，其次是檔名開頭的 `YYYY-MM-DD` | Knowmon 自動記錄             |
| 一篇有幾個 | 最多一個；可能沒有                                    | 可能有很多次                 |
| 範例       | 會議紀錄的會議日期                                    | 你整理那份紀錄的日子         |

**範例**：10/8 補寫 10/1 的會議紀錄（`date: 2026-10-01`），10/15 又改了幾句。

- 事件時間：10/1
- 寫作時間：10/8、10/15

讀書心得、概念筆記這類沒有日期的筆記，沒有事件時間，但仍然有寫作時間。只是**打開來看**不算寫作時間。

設定事件時間的方法見 [屬性](properties.md#date事件日期)。

## 時間邊

Knowmon 依時間自動產生三種關聯，顯示在 [圖譜](graph.md) 中：

### Session：一起寫的筆記

> 「這篇是和哪些筆記一起寫的？」

Knowmon 把你的編輯紀錄依時間排好，只要停下來超過 **30 分鐘**，就算新的一段工作時間（session）。同一個 session 裡編輯過的筆記會兩兩相連，不論在哪個資料夾。

- 只要一直有在寫，session 就會延續，沒有總長度限制。
- 只算**編輯**。打開閱讀、或第一次開啟 vault 時補記的「建立」都不算。
- 一個 session 編輯超過 **20 篇**時，多半是同步工具、全域取代、`git pull` 之類的批次操作，這種 session 不產生任何線。
- 需要在 Knowmon 裡（或 Knowmon 開著時）實際編輯過才會有。剛開啟的 vault 還沒有 Session 邊。

**範例**：某天下午你連續改了「2026-10-05」日記、「原子習慣」、「Knowmon 開發日誌」，這三篇就會以 Session 線互相連起來，即使它們分屬三個資料夾。

### Same day：同一天的事

> 「同一天還發生了什麼？」

事件時間相同的筆記會相連。可以放寬到相差幾天內，此時相差越多天，關聯越弱。

**範例**：`日記/2026-10-01.md` 與 `date: 2026-10-01` 的「Knowmon 開發日誌」會以 Same day 相連。

### Sequence：前一篇與下一篇

> 「這篇的上一篇、下一篇是什麼？」

**同一個資料夾**（包含 vault 根目錄）裡有事件時間的筆記，依日期排好，每篇連到前一篇與後一篇，形成一條鏈。最典型的就是日記：

```
日記/2026-10-04 ── 日記/2026-10-05 ── 日記/2026-10-06
```

10/4 與 10/6 不直接相連。如果你用資料夾區分主題（例如 `專案/Knowmon/`），同一主題裡的筆記也會依時間串起來。

### Session 和 Sequence 的差別

|        | Session                     | Sequence         |
| ------ | --------------------------- | ---------------- |
| 看的是 | 寫作時間（到分鐘）          | 事件時間（到天） |
| 範圍   | 跨資料夾                    | 同一資料夾內     |
| 形狀   | 同一 session 的筆記全部互連 | 前後相連成一條鏈 |
| 需要   | 在 App 裡實際編輯過         | 筆記有日期       |

## 時間軸

按 `Ctrl+Shift+T` 或左側欄的 **Timeline**，在主區域開啟時間軸分頁。它有兩種模式，在工具列切換：

### Event date 模式

依事件時間列出筆記，新的在上，同一天的放在一起。最下面顯示沒有日期的筆記有幾篇。

適合：回顧日記、找某天的會議紀錄。

### Written 模式

依天列出你的**每一段工作時間**：開始與結束時間，以及那段時間編輯了哪些筆記；那段時間新建立的筆記會標示 **new**。

適合：「我昨天下午到底做了什麼？」、看自己的寫作習慣。

> Written 模式的 session 和 Session 邊用的是同一個規則，但這裡也把「建立筆記」算進去，因為建立筆記本身就是寫作的一部分。跨過午夜的 session 算在開始的那一天。

### 操作

- 上方的長條圖是每個月的數量，**點擊長條**會捲到該月。
- 點擊筆記在目前分頁開啟，`Ctrl+點擊`開在新分頁。
- 時間軸和圖譜一樣，分頁存在期間保持原狀，切走再切回來不會重新載入。

## 設定

在圖譜或時間軸的工具列按 **Settings**，開啟「Time & link settings」。設定存在這個 vault 的 `.knowmon/settings.json`，跟著 vault 走（換台電腦打開同一個 vault，設定還在）。

| 設定                  | 預設    | 範圍  | 影響                                                   |
| --------------------- | ------- | ----- | ------------------------------------------------------ |
| Session gap           | 30 分鐘 | 5–240 | 停下來超過多久算新的 session；影響 Session 邊與時間軸  |
| Max notes per session | 20 篇   | 2–200 | 超過這個篇數的 session 視為批次操作，不產生 Session 邊 |
| Same-day window       | 0 天    | 0–7   | 事件時間相差幾天內算 Same day；0 = 只算同一天          |

同一個視窗下方還有 Semantic 邊的設定，見 [圖譜](graph.md#semantic-邊)。

按 **Save** 後圖譜立即更新。

**怎麼調整？**

- 你習慣寫一下、去做別的事、再回來寫 → 把 Session gap 調大（例如 60）。
- 你會在一個 session 裡整理大量筆記，卻沒有 Session 邊 → 把 Max notes per session 調大。
- 你想看「同一週」發生的事 → Same-day window 設成 3～7。

## 須知

- 寫作時間**從開始使用 Knowmon 之後**才有紀錄。第一次開啟既有的 vault 時，每篇筆記會以檔案的建立時間補記一筆「建立」。
- Knowmon 沒開時你在其他編輯器改了很多次，下次開啟時只會記成一次編輯（時間為檔案最後修改時間）。
- 同一篇筆記的同一種紀錄 60 秒內只記一次，所以自動儲存不會產生大量紀錄。
- 日期一律使用你電腦的本地時區。
- 編輯歷程存在 `.knowmon/events.jsonl`，這是**無法重建的資料**，請不要刪除。見 [檔案與資料](files-and-data.md)。
